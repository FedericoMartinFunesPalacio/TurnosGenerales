SEGUIR ESTAS REGLAS OBLIGATORIAMENTE PARA LA CONSTRUCCION DEL PROYECTO


REGLAMENTO GENERAL:
1) Solo trabajar con lo que indica la consigna. Cualquier acción fuera de esto puede generar errores o inconsistencias
2) Leer la consigna. Revisar atentamente los archivos "readme.md" o "txt" y entender claramente los requerimientos del trabajo
3) No crear archivos ".md", ".bat" que no se pidan en la consigna o que yo no te pida.
4) No modificar archivos cruciales del proyecto como POM o Config.json
5) Familiarizarse con el scaffolding completo, la organización de las carpetas, modulos y dependencias
6) Usar las dependencias que están en el proyecto, no agregar otras sin mi aprobación
7) Revisar los archivos cruciales para entendes la configuración del proyecto
8) Seguir los ejemplos proporcionados en el código para la construcción de archivos similares (copiar la sintaxis, el uso de etiquetas, etc.)
9) Es mas importante que funcione antes de que sea eficiente, no importa la cantidad de recursos que consuma siempre que funcione el proyecto


REGLAS IMPORTANTES SOBRE BACKEND:
1) Respetar las capas de datos: Entity -> DTO
2) Respetar las capas de dominio: Repository -> Service -> Controller
3) Usar Inyección por constructor (IoC)
4) Respetar las respuestas de los endpoints pedidos
5) Correcto manejo de errores y devolución de estos adecuada
6) Base de datos en H2
7) Testing unitario con JUnit, Mockito y Spy. Lograr 80% coverange.
8) Las fechas y/o horario deben respetar el formato dd-MM-yyyy y hh-mm-ss
9) Respetar el nombrado en camelCase dentro del codigo y snake_case en los envios de los endpoints

REGLAS IMPORTANTES SOBRE FRONTEND:
1) Debes usar si o si las nuevas directivas de angular @if @else (la nueva sintaxis de control de flujo de Angular 17+). No se puede usar las directivas legacy (NgIf, NgFor, etc.)
2) Debes usar forms-template drive (el clásico [(ngModel)])
3) El service del proyeto debe manejar todas las solicitudes hacia las APIs con HttpClient y con Observables
	3.1) Los Observables se manejan con la libreria RxJS y su suscripcion
4) Respetar cada archivo del componente, usar correctamente cada archivo para su fin (HTML, CSS y TS)
5) Realizar la comunicacion de los componentes con @Input, @Output o servicio como ultima opcion
6) Si el componente redirecciona a una vista nueva a travez de ruteo, verificar bien el enlace con RouterOulet y verificar su ruta en archivo app.routes
7) Usar solo CSS, no tailwind. Siempre debe verse ordenado todo (Cards, colores para los estados, tablas legibles)
8) Mapeo de DTOS: Observa como se envia la información desde el Backend y como se recibe en el Frontend. Cuidado con la convercion de snake_case a camelCase


PASOS BACKEND:
Una vez leido y entendido la actividad a realizar, seguir los siguientes pasos:
1) Realizar los archivos Entity en su carpeta correspondiente con sus etiquetas correctas y relacionadas de manera correcta si fuera necesario
2) Realizar las interfaces Repository para cada Entity utilizando JPA como se proporciona en los ejemplos
3) Realizar los DTOS de Request y/o Responses necesarios para el manejo de datos de los endpoints
4) Realizar las interfaces Service y sus Implementaciones con la logica necesaria para cumplir lo que pide la consigna.
	IMPORTANTE, tener en cuenta validaciones y correcto manejo de errores en esta parte. Si la consigna pide devolver un error especifico respetarlo.
5) Realizar los Controllers con los endpoints necesarios y planeados desde el Service
6) Una vez este todo andando correctamente, realizar los Test unitarios de cada Service y Controller para lograr el 80% de coverange
7) No realizar cambios si el codigo es funcional, a menos que lo pida

PASOS FRONTEND:
Una vez que el Backend es funcional y se entiende que hay que hacer en este lado, seguir los siguientes pasos:
1) Conocer cada componente y respetar su funcion y posicionamiento. Si fantara un componente clave lo creas siendo standalone
2) Realizar los modelos correspondientes siguiendo los DTOS del Backend y respetando que se envian en snake_case por la API
3) Realizar el archivo Service que va a manejar toda la comunicacion con el Backend. Usar HttpClient y Observables con suscripcion.
4) Realizar cada componente con su logica pensada respetando las reglas
5) Conectar los componentes con sus vistas y manejar su comunicacion
6) Corroborar el ruteo correcto con cada componente
